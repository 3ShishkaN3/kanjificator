# Kanjificator - Сервер распознавания японских иероглифов

## Описание проекта

Kanjificator - это серверное приложение для распознавания рукописных японских иероглифов (кандзи) на основе технологии машинного обучения. Сервер использует библиотеку Zinnia для анализа геометрии рукописных штрихов и определения наиболее вероятных символов.

Проект предоставляет REST API для интеграции распознавания иероглифов в другие приложения. Клиентское приложение на Tkinter включено исключительно для тестирования и демонстрации работы технологии.

## Архитектура сервера

Сервер реализован на Python с использованием веб-фреймворка Flask. Основные компоненты:

### Инициализация и загрузка модели

При запуске сервера выполняется загрузка предварительно обученной модели [Zinnia](https://deb.debian.org/debian/pool/main/z/zinnia/zinnia_0.06.orig.tar.gz):

```python
MODEL_PATH = "/app/models/handwriting-ja.model"
recognizer = zinnia.Recognizer()
if not recognizer.open(MODEL_PATH):
    print(f"ERROR: Could not open model at {MODEL_PATH}")
    exit(1)
```

Модель `handwriting-ja.model` представляет собой файл с обученными параметрами для распознавания японских иероглифов.

### Обработка запросов

Сервер предоставляет единственный эндпоинт `/recognize`, принимающий POST-запросы с данными о рукописных штрихах в формате JSON.

### Процесс распознавания

1. **Парсинг входных данных**: Извлечение ширины, высоты области и массива штрихов
2. **Создание объекта Character**: Формирование объекта Zinnia Character для представления символа
3. **Добавление штрихов**: Последовательное добавление точек каждого штриха в объект
4. **Классификация**: Вызов метода `recognizer.classify()` для получения кандидатов
5. **Формирование ответа**: Возврат массива кандидатов с символами и оценками уверенности

## Структура данных

### Входные данные (запрос)

Сервер ожидает JSON-объект со следующей структурой:

```json
{
  "width": 300,
  "height": 300,
  "strokes": [
    [[x1, y1], [x2, y2], ...],
    [[x3, y3], [x4, y4], ...]
  ]
}
```

**Поля:**
- `width` (integer): Ширина области рисования в пикселях (по умолчанию 1000)
- `height` (integer): Высота области рисования в пикселях (по умолчанию 1000)
- `strokes` (array): Массив штрихов, где каждый штрих - массив точек [x, y]

### Выходные данные (ответ)

Сервер возвращает массив объектов-кандидатов:

```json
[
  {"value": "日", "score": 0.95},
  {"value": "目", "score": 0.87},
  {"value": "田", "score": 0.82}
]
```

**Поля каждого кандидата:**
- `value` (string): Распознанный иероглиф в виде Unicode-символа
- `score` (float): Оценка уверенности модели (от 0.0 до 1.0)

## Установка и запуск

### Требования к системе

- Docker для контейнеризованного развертывания
- Python 3.9+ (для запуска без Docker)
- Linux/Windows/MacOS

### Запуск с Docker (рекомендуемый способ)

1. Установите Docker
2. Клонируйте репозиторий
3. Перейдите в директорию проекта
4. Соберите образ:

```bash
docker build -t kanjificator .
```

5. Запустите контейнер:

```bash
docker run -p 5000:5000 kanjificator
```

Сервер будет доступен на http://localhost:5000

### Запуск без Docker

**Внимание:** Этот способ требует ручной компиляции Zinnia и установки Python bindings, что является сложным процессом. Рекомендуется использовать Docker.

1. Установите Python зависимости:

```bash
pip install flask
```

2. Соберите и установите Zinnia с Python bindings (см. Dockerfile для деталей)
3. Скачайте модель распознавания
4. Запустите сервер:

```bash
python server.py
```

## API сервера

### POST /recognize

Основной эндпоинт для распознавания иероглифов.

**Метод:** POST  
**Content-Type:** application/json  
**Тело запроса:** JSON с данными штрихов (см. структуру выше)  
**Ответ:** JSON массив кандидатов (см. структуру выше)

**Пример использования с curl:**

```bash
curl -X POST http://localhost:5000/recognize \
  -H "Content-Type: application/json" \
  -d '{
    "width": 300,
    "height": 300,
    "strokes": [
      [[50, 50], [100, 100], [150, 50]]
    ]
  }'
```

**Обработка ошибок:**
- Если штрихи отсутствуют, возвращается пустой массив `[]`
- При ошибках загрузки модели сервер завершается с кодом 1
- Сетевые ошибки обрабатываются на стороне клиента

## Тестирование

Для тестирования работы сервера включено клиентское приложение на Tkinter (`client.py`). Оно предоставляет графический интерфейс для рисования иероглифов и отправки данных на сервер.

**Запуск тестирования:**
1. Запустите сервер
2. В отдельном терминале выполните:

```bash
python client.py
```

3. Рисуйте иероглифы на холсте - результаты появятся в списке справа

Клиентское приложение использует библиотеку `requests` для отправки HTTP-запросов и служит исключительно для демонстрации функциональности API.

## Как работает распознавание

### Детальный алгоритм

1. **Инициализация Character**: Создается объект `zinnia.Character()` для представления символа
2. **Установка размеров**: Вызываются методы `set_width()` и `set_height()` для задания области
3. **Добавление штрихов**: Для каждого штриха вызывается `add(stroke_idx, x, y)` для каждой точки
4. **Классификация**: Метод `recognizer.classify(character, 10)` возвращает топ-10 кандидатов
5. **Извлечение результатов**: Для каждого кандидата получаются `value` и `score`

### Особенности алгоритма Zinnia

- Использует статистические методы для сравнения с обученными паттернами
- Учитывает последовательность и направление штрихов
- Работает с нормализованными координатами относительно заданной области
- Возвращает вероятностные оценки для ранжирования кандидатов

## Ограничения

- Поддержка только японских иероглифов (кандзи)
- Точность зависит от качества рукописного ввода
- Модель обучена на ограниченном наборе символов (~2000 иероглифов)
- Работает только локально, без облачных сервисов
- Максимум 10 кандидатов на распознавание
